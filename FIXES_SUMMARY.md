### 3. ✅ Token Expiry Causing "Need to Resign" Issues
**Problem**: Users had to constantly sign in again when JWT tokens expired (typically after 1 hour).

**Root Cause**: 
- Refresh tokens were being generated by backend but NOT stored by frontend
- Frontend `login()` function wasn't accepting or storing refresh tokens
- Extension wasn't receiving or storing refresh tokens either

**Solution**:
- **Backend** (already working): `authService.js` generates both `accessToken` and `refreshToken`, `/auth/refresh` endpoint exists and works
- **Frontend Website**: 
  - Updated `AuthContext.tsx` to accept and store `refreshToken` in `localStorage`
  - Updated `login()` function signature to accept optional third parameter: `refreshToken`
  - Added code to sync refresh token to extension storage when login occurs
  - Added refresh token cleanup on logout
- **Frontend Pages**:
  - Updated `Register.tsx` to pass `data.refreshToken` to `login()`
  - Updated `Login.tsx` to pass `data.refreshToken` to `login()`
- **Extension** (already working): `auth.js` already has full refresh token logic that:
  - Checks token expiration 5 minutes before expiry
  - Automatically calls `/auth/refresh` endpoint
  - Updates stored `authToken` with new token
  - Only requires user to re-login if refresh token itself is invalid

**Files Modified**:
- `Crm-sync/context/AuthContext.tsx` (added refreshToken storage and extension sync)
- `Crm-sync/pages/Register.tsx` (line 73: added refreshToken parameter)
- `Crm-sync/pages/Login.tsx` (line 59: added refreshToken parameter)

## How Token Refresh Works Now

### Flow:
1. **User logs in/registers** → Backend returns `{ accessToken, refreshToken, user }`
2. **Website stores both tokens**:
   - `localStorage.setItem('token', accessToken)`
   - `localStorage.setItem('refreshToken', refreshToken)`
3. **Website syncs to extension** (if installed):
   - `chrome.storage.local.set({ authToken, refreshToken, user, ... })`
4. **5 minutes before accessToken expires**:
   - Extension `auth.js::getAuthToken()` detects expiration
   - Automatically calls `refreshAccessToken(refreshToken)`
   - Updates `authToken` in storage with new token
   - Returns new token for API calls
5. **User stays logged in** without interruption!

### Only requires re-login when:
- Refresh token itself expires (typically 7-30 days, or on password change)
- User explicitly logs out
- User clears browser data

## Console Commands for Debugging

### Check if refresh token is stored:
```javascript
// In website
console.log('Refresh token:', localStorage.getItem('refreshToken'));

// In extension
chrome.storage.local.get(['refreshToken'], r => console.log('Refresh token:', r.refreshToken));
```

### Manually trigger token refresh:
```javascript
// In extension popup console
await window.CRMSyncAuth.getAuthToken(); // Will auto-refresh if near expiry
```

### Check token expiration time:
```javascript
const token = localStorage.getItem('token');
const payload = JSON.parse(atob(token.split('.')[1]));
const expiresAt = new Date(payload.exp * 1000);
console.log('Token expires at:', expiresAt.toLocaleString());
console.log('Time until expiry:', Math.round((expiresAt - Date.now()) / 60000), 'minutes');
```
